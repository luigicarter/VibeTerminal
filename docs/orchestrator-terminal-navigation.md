# Terminal navigation evidence

The orchestrator receives an application-owned provider guide with explicit terminal reads. Model-facing session directories omit repeated guides through `includeNavigationGuide:false`; the summary API retains its default guide for compatibility. Commands require an observed ready composer; keys require an observed menu and its current bindings. Read again after each action. Printed status output may need no dismissal. Exit, reset, purchase, authentication and configuration changes are outside inspection.

All currently supported native provider IDs have explicit profiles; Claude and Kimi custom launchers share their underlying CLI grammar. A future supported provider falls back to visible help/menu discovery until its commands are verified. Unknown identities never inherit guessed grammar. Structured Fusion/Open Fusion flags take precedence over underlying provider identity; these panes use structured state/history. Plain shells never receive native coding CLI slash commands.

Documentation and upstream source can move ahead of installed binaries; local binary versions do not identify every running pane. The reviewed installed Lina Terminal 0.1.103 lacked this guide: source changes here do not establish an installed-app update. Report only displayed figures, including used/remaining and window/reset distinctions. Token/context usage, activity analytics and API cost do not prove subscription quota.

Verification uses `scripts/backend/orchestrator-terminal-guide.test.cjs` and
`orchestrator-terminal-inspection.test.cjs` for catalog coverage and the native
observe/act/read/report flow across all ten provider IDs. The optional live harness
`scripts/qa/orchestrator-terminal-inspection-live.cjs --case <name>` tests a selected
scenario with synthetic terminals. `--self-test` uses no network or credentials;
`VIBE_LIVE_MODEL` selects a reference model for that harness process only, while
the report records both configured and tested models. The installed app's model
setting is unchanged. Synthetic screens do not establish physical CLI rendering.
