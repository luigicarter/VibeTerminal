# Codex Web

Revised September 11, 2026. **Codex Web runs the actual bundled Codex CLI directly in Lina's normal terminal pane.** Codex owns the terminal, conversation history, resume, model picker, permissions and agent loop. Lina supplies the private Web connection and account model catalog. There is no custom chat UI, remote-session proxy or second conversation store.

## Local history and settings

`CODEX_HOME` is `<Lina userData>/codex-web/codex-home`. Codex writes its normal `sessions/` rollout files, `history.jsonl`, thread database, memories and settings there. Closing or restarting a pane does not remove them. Use native **/resume** or `codex-web resume`; forwarded CLI commands use this same home. Web logout keeps local history, as normal Codex logout does.

The development preview uses `%APPDATA%/vibe-terminal-codex-web-preview/codex-web/codex-home`, separate from the installed app. Old prototype `lina-panes/` metadata may still exist, but production no longer reads or writes it. Existing native session files remain available.

The global Codex login and history are not imported or changed. Global skills, plugins and rules are linked into the private home. MCP/plugin/skill configuration, user instructions and project trust settings are shared. Sandbox, approval, Windows sandbox, permission-profile and shell-environment settings inherit the normal Codex configuration, including its selected profile. The launcher no longer forces a separate read-only policy. Private native authentication uses file storage, avoiding the global credential-store login; Web inference itself needs only the browser login.

## User flow

1. Open **New session → Codex Web**. With a cached account and model catalog, the native terminal opens while login validation runs in the background. Only ChatGPT Web sign-in is required; there is no second native Codex login step.
2. If needed, complete browser sign-in and keep its window open until Lina saves the session.
3. The account catalog loads automatically, then the normal Codex terminal starts. GPT-6 Astra is the default when available; a valid saved native model choice takes precedence. Use native **/model** to select models and reasoning levels. There is no startup model-number prompt.
4. Use the pane menu for **ChatGPT Web sign in**, **ChatGPT Web sign out**, or **Refresh Web models**. Shell commands `codex-web login` and `codex-web logout` manage the same Web account. Web authentication belongs to these actions; Codex's own authentication commands do not manage browser cookies.

Sign-in and model refresh restart an idle terminal when needed. Resume its saved conversation with /resume. Repeated sign-in actions share the pending operation. Logout removes the Web session and cached models but preserves native local history. Expired saved credentials display a sign-in message; transient connection failures preserve the cache and offer retry, sign-in or diagnostics. The next account receives its own model catalog.

Local coding tools now work through the native CLI without the separate Full harness tunnel/connector setup. The Web model returns structured requests for the exact native tool inventory. Lina translates these to native tool events; Codex executes them, applies its permissions and supplies results to the next model round. No separate Codex Web GPT setup app, window or tray icon appears. The older optional upstream connector code remains internal and is no longer a startup requirement or pane menu action.

## Native provider and models

- Provider ID `codex_web` uses a private loopback Responses URL and a file-backed account catalog. `requires_openai_auth=false` avoids a second login and native Codex quota fetching. Its provider name is `OpenAI`: Codex uses that exact manufacturer name to preserve message/turn metadata needed by the bridge.
- Native Fast mode is disabled, service tier defaults to standard, and catalog rows have no Fast tiers. The bridge rejects unsupported tiers. Native Codex quota/reset figures are not advertised. Context indicators remain Codex estimates; Web plan usage is checked in ChatGPT.
- Discovery reads authenticated ChatGPT model metadata inside the owned browser. Tokens stay in the page. Enabled picker versions/categories and selectable Work models determine the list and reasoning controls.
- Native IDs follow Codex conventions, such as `gpt-6-astra` and `gpt-5.6-sol`; old `chatgpt-web/<account model slug>` IDs remain aliases. The bridge selects the exact account model and verifies the outgoing conversation request before sending; a mismatch fails instead of substituting another model.
- `/model` shows reasoning models, including Pro. When an account has a Work model, its overlapping Thinking/Chat entry is hidden; accounts without that Work model retain their Thinking entry. Instant and Auto are hidden. This account currently has eight visible choices: Astra, Sol, Terra, Luna, GPT-5.5, and GPT-5.5/5.6/6 Pro. All 14 account routes remain in native metadata so saved selections/history keep the exact model and effort; the image tool can still use its private image-capable route. Picker visibility never grants access to an unavailable account model.
- Web context uses a conservative adapter budget capped at 103,000 tokens and the account catalog's limit, with earlier compaction. This is not a claim about the underlying model's maximum context.
- The native catalog template is pinned public Codex data, bundled with its license. Inherited native model identity and Fast tiers are removed while coding instructions remain. It requires no authenticated native model endpoint.

## Implementation

`backend/codexWebTerminal.cjs` is a connection bootstrap that spawns native Codex with inherited terminal I/O. Codex Web has its own **0.154.0** CLI payload under `vendor/codex-web/native/win32-x64/`, including the normal helper executables and resources. `prepare-codex-web-cli.cjs` prepares the pinned official npm package, verifies its package integrity and executable version, and includes it in the existing Codex Web packaged resource. It does not use or modify the global executable or Fusion's older bundle. `codexWebNative.cjs` resolves only this app-owned CLI, supplies the route/catalog and strips launcher credentials from the child environment. Configuration flags stay grouped at the active command level for native argument compatibility.

The interactive child explicitly enables truecolor and removes an inherited `NO_COLOR` restriction. Agent-launched previews inherited `NO_COLOR=1`, which suppressed native diff colors. This change applies only to the embedded terminal child, preserving Codex's own red/green diff renderer and backgrounds. No custom diff UI or syntax recoloring is added. The offline native color fixture starts with `NO_COLOR=1` and `TERM=dumb`, executes a real patch, and checks xterm cells for red deletion signs, green insertion signs and distinct RGB backgrounds.

`codexWebToolRelay.cjs` streams ordinary Web answers as text arrives. Local tool requests use a round-bound `LINA-TOOL-CALL` marker and fenced JSON; the entire batch is validated against the requested inventory before any executable event is emitted. Legacy JSON envelopes remain accepted. Strict structured final outputs and required-tool responses stay buffered until validated. The relay never executes commands, implements approvals or owns an agent loop. Native Codex owns tools, MCP discovery, subagents and their results.

The image MCP server is required to initialize and its `mcp__lina_images` namespace is directly exposed in the first native model request through `features.code_mode.direct_only_tool_namespaces`. Existing direct namespaces and the configured code-mode enabled state are preserved. Image generation no longer depends on the model first guessing that it should search for a tool. Both initial and retained Web prompts explicitly distinguish this available image service from Temporary Chat's built-in limitations. Disabled/unavailable tools are not advertised as available. These settings use the [official Codex configuration surface](https://learn.chatgpt.com/docs/config-file/config-reference).

Stock Codex 0.154.0 does not implement the upstream bridge's `Interrupt` hook event. Lina therefore treats an unfinished native response-stream abort as cancellation of its owned Web execution. It stops the owned page, retains a cancelled journal entry to prevent automatic resubmission, and leaves completed response replay intact. A dropped network connection during an unfinished response also cancels that operation; the user can retry. This does not cancel another native thread's stream. The legacy upstream hook journal remains compatibility metadata, not the cancellation mechanism.

The native MCP client can abandon a tool future without delivering `notifications/cancelled`. During an image call, `codexWebNativeCancellation.cjs` uses the MCP thread/turn metadata to observe only that turn's `turn_aborted` record in native local history. Reads are incremental, bounded, and stop when the call settles; image/prompt contents are neither copied nor logged. Standard MCP cancellation, process shutdown, and late-result suppression remain handled too. The image worker stops its owned browser operation and releases its lease. A normal saved native session is required for this binding; image generation with `--ephemeral` is explicitly unsupported rather than starting an unbound operation.

`codexWebConversation.cjs` reuses a browser conversation only when the new native input extends its previous history and the model, system instructions and tool inventory still match. Continuations send only new messages/results instead of uploading the full tool inventory again. Changed history, compaction, changed tool schemas and a new proxy process get fresh browser rounds. Work models, including Astra, deliberately use fresh rounds: live testing showed that ChatGPT resets their menu after a reply and a retained effort adjustment can select Sol. Every outgoing request still verifies the exact requested model; mismatches are blocked before submission. The native local history remains authoritative throughout.

Model IDs shown by native `/model` and its status line follow Codex naming conventions (`gpt-6-astra`, `gpt-5.6-sol`, and explicit Web variants such as `gpt-5.6-sol-thinking`). Exact Web slugs remain private routing metadata; legacy `chatgpt-web/...` IDs still work and retain saved effort. Cached catalogs migrate their names locally. This changes presentation, not account availability or authentication. The Web tool contract also preserves native freeform grammars, including the full `apply_patch` syntax. An explicit native Browser Use security-policy rejection stops the current Web turn before another model/tool action, preserving completed files and history. See [the flying-dog thread review](codex-web-thread-review-2026-09-11.md) for the native diff display, patch recovery, timing, and browser-verification evidence.

The bridge avoids a second navigation when it has already opened the selected model's Temporary Chat. Response timing is recorded in bounded `bridge/logs/lina-response-timing.jsonl` entries containing model, elapsed times, counts and a round hash, without prompt or response text.

`codexWebImages.cjs` adds a private `lina_images.generate_image` MCP tool for generation and reference-based editing. Optional `referenced_image_paths` upload the actual selected local images in their declared order. It uses the cached Web account and saves generated PNG/JPEG/WebP files under `<Lina userData>/codex-web/generated-images/`. Results contain short filename/path/dimensions receipts; image bytes stay on disk until native `view_image` is needed. Downloads validate origins, redirects, size and signatures, and distinguish generated widgets from user reference images and their alternate previews. Cancellation releases the browser lease; errors do not automatically repeat generation. ChatGPT image creation was unavailable in Temporary Chat, so this uses a separate regular image chat containing only the supplied prompt and reference images. Those inputs and the result can appear in Web history. Bounded `bridge/logs/lina-images.jsonl` entries record stages, elapsed times and counts, without prompts, image bytes or credentials. Timeout errors do not claim that login expired.

Generated filenames are clickable only in Codex Web panes. Clicking uses the existing pane-action channel to open the saved image with the user's configured image viewer; generation itself never opens another app. The backend accepts only generated-image filenames in Lina's image directory, validates their resolved location and image signature, and rejects stale panes. Missing files and viewer failures produce a visible error. General file/protocol links remain disabled.

Normal Codex likewise saves generated originals under `$CODEX_HOME/generated_images/<session>/<image>.png`, then instructs the agent to copy an image when it belongs at another path, preserving the original unless deletion was requested. The Web image tool's description and receipt now state the same placement policy. A generation-tool destination argument is not needed: normal Codex file tools perform the project copy, subject to native permissions. The shared image skill remains available.

Codex Web Ctrl+V/context-menu paste now accepts clipboard images and copied image files. Clipboard pixels are stored under the private `input-images/` directory; the system clipboard is not changed. File drops use Electron's native file paths. `terminalImages.ts` passes validated paths through Codex's bracketed-paste attachment handling, yielding normal `[Image #N]` attachments that the user can inspect/remove before submitting. Asynchronous results are fenced against pane restart/closure. Ordinary text paste and other terminal providers retain their existing behavior. Native Alt+V remains forwarded, but does not have separate live clipboard acceptance.

Input limits remain explicit: PNG/JPEG/GIF/WebP, at most 20 MB each and 50 MB combined, with ten images per Web request. Oversized paste/drop/reference batches are rejected before upload. More than ten images on the newest user message produces a visible error before sending a Web request, rather than discarding part of that input. Older history images beyond the Web attachment budget retain an omission note in the model context; native local history remains intact.

Computer Use follows normal Codex configuration: inherited plugins and MCP servers expose the installed runtime, and missing-runtime errors are returned normally. Lina does not supply or launch a replacement desktop-control app. Native subagents inherit the selected Web provider and remain ordinary local Codex child sessions, subject to their configured permissions and the shared browser capacity.

Lina manages the bundled executable, so this launcher sets `check_for_update_on_startup=false`. A cached newer native CLI version must not interrupt startup or offer an updater for another installation. The native TUI smoke always seeds a newer cached version and checks that the model picker opens without an update notice.

`codexWebHost.cjs` supervises the bridge and authenticated local connection actions. It does not send chat requests, interpret approvals or store transcripts. `codexWebLauncher.cjs` runs the hidden upstream Electron browser host. `codexWebModelDiscovery.cjs` handles account metadata and model selection. `codexWebBrowserLogin.cjs` owns the temporary login profile.

Startup uses Lina's bundled runtime directly. Full manifest/checksum validation happens during resource preparation instead of copying and hashing the full runtime at every launch. Local provider startup runs alongside authentication. A previously verified account's cached catalog can open the CLI while authentication is still pending; this does not mark the current login authenticated. Stale model catalogs refresh in the same background operation. Without usable cached metadata, first-time setup still waits for authentication and discovery.

When **Lina itself opens**, its app-ready handler schedules `codexWebHost.prewarm()` after creating the main window. An existing cached Web profile starts its hidden connection/validation then, before any Codex Web pane is needed. Fresh profiles are skipped; prewarm never opens a sign-in browser or creates a terminal session. A later pane reuses that connection. If a pane opens immediately during app startup, is restarted, or prewarm failed, the existing cached-startup/retry path remains available and shares any connection preparation already in progress. Background failures are logged and cannot hold up Lina's window.

`codexWebStartup.cjs` supplies the background validation and request gate. The existing private browser control endpoint holds model requests until validation finishes, before creating any browser turn or transmitting task context. Expired credentials and unexpected account changes block requests and produce a single pane error with sign-in guidance. Explicit account switching waits for validation to settle and resets its account binding. Confirmed logout/expiry/account changes invalidate cached models while preserving native history. Transient network failures retain the saved cache and permit validation to recover on a subsequent request. Cached local history and terminal controls remain usable. An updated catalog is written for subsequent native launches; the pane menu can explicitly refresh/restart the picker.

`codexWebSupport.cjs` and `codexWebConfig.cjs` preserve private configuration, shared capabilities and upstream routing/hook journal markers. Operational logs are bounded and contain safe categories, stages and references rather than prompts or credentials. Native session history remains normal local Codex user data. Authentication loss prompts sign-in; connection errors retain the login. The launcher never automatically resubmits a prompt. Native Codex owns retry/continuation behavior.

## Development

- `npm run prepare:codex-web`: prepare pinned upstream 5.0.6, Bun 1.4.0 and the separate Codex 0.154.0 native payload in ignored `vendor/codex-web/`, including bundle/package integrity verification. Patches live in `scripts/dev/patch-codex-web.cjs`; overlays skip identical live runtime files.
- `npm run test:codex-web`: auth/config isolation, account models, native argument forwarding, login/setup and redacted diagnostics. Host tests assert no duplicate conversation store is created.
- `npm run smoke:codex-web`: isolated native authentication handshake, actual native TUI over a PTY, Electron/xterm clipboard/drop attachments, initial tool grammar/exposure, and native red/green diff colors using offline fixtures. No Web inference or system clipboard modification is performed.
- `node scripts/qa/codex-web-tui-smoke.cjs --cached-models --choose-next --shared-permissions`: actual native /model selection/persistence against cached metadata and the user's prepared sandbox settings, including cached update-prompt regression coverage. Sends no inference request.
- Add `--pending-login` to that smoke command to prove the native UI remains usable while background login validation is pending.
- `npm run build`: TypeScript and production renderer build.
- `node scripts/app/preview.cjs`: launch the built app with the separate persistent preview profile.
