# Lina Terminal 0.1.126

- The Orchestrator asks before opening a terminal whose name it does not recognize, instead of guessing a provider or creating the wrong pane. The question keeps the original task and its constraints, so the answer only needs to correct the name or the count.
- When one requested terminal fails to start, the others in the same request still receive their work. Each piece of work now settles on its own: a sibling's failure no longer marks delivered work as failed, and finishing that work no longer hides the failure.
- Retrying a failed launch reuses the recovered terminal and never re-sends work that already went out. Cancelling keeps late terminals from being given tasks.
- Partly completed requests report what actually happened, naming each terminal once and without announcing the request as finished.
- Startup diagnostics name the phase and the last blocker that stopped a terminal instead of calling every failure an input-readiness timeout, and are limited to a small number of records per wait.
- Automatic voice capture now waits 1.5 seconds of quiet before sending. The 600 ms confidence shortcut that could cut a sentence off during a thinking pause has been removed. “Pause before sending (seconds)” in Orchestrator & voice settings accepts 1 to 3 seconds and takes effect on the next recording.
- Speaking again after a pause still discards the early guess, so only the complete sentence is sent. Holding Space and clicking Send are unchanged.
- The Chats section is hidden by default. Its catalog, drafts, recovery and exact native resume keep running underneath, and setting the renderer switch `lina:chats:visible` to `1` restores the section with every existing chat in place.

Updates apply through Check for update → Update → Restart. Publication does not restart an active workspace.
