# Lina Terminal 0.1.125

- Extra spare terminals are now opt-in. Existing default-on settings are turned off on upgrade; enable “Keep a spare agent ready” explicitly if wanted. Manually used spares are no longer automatically closed.
- Follow-ups stay with the same task when a freshly opened agent first reports its conversation ID, preventing false “different task” errors.
- Requests naming an existing busy terminal reuse that conversation. Terminal handles, multiple-handle commands, named project scopes, and replies that name a suggested terminal are resolved more reliably.
- Task descriptions about opening terminals no longer count as launch requests. Negative answers do not authorize new panes, and uniquely named providers are preserved instead of substituted.
- Close-then-open-and-prompt requests are checked for omitted operations before execution. Blank openings execute their bound actions directly, avoiding repeated malformed model calls.
- Explicit “prompt it with Hi” requests send the supplied greeting instead of passing the launch instructions to the worker.
- Shutdown waits for pending pane-memory updates to finish before closing its storage.

Updates apply through Check for update → Update → Restart. Publication does not restart an active workspace.
