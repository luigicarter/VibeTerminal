# Lina Terminal 0.1.124

- The Orchestrator now keeps one model of every terminal and shows it identically to you, to Lina and to the app: a short handle (T1, T2, …), what the pane is doing, which task it holds, who owns it, when it was last touched and what it last produced. Lina names panes by handle only, so "stop T3", "tell it to continue" and "which one needs me" resolve in code, before any model call, from that one record. Requests that used to take several model calls per turn now average about one, and the first effect in a pane lands in a few seconds rather than ten or more.
- "Stop", "interrupt" and "pause" keep the pane and send an interrupt; "close", "quit" and "kill" close it. "Stop that last terminal you worked on" no longer plans as a prompt, or as a close of three panes.
- New work Lina puts in a free or freshly opened pane no longer waits for another agent's turn in the same project. A task owns its pane, not the whole working folder; work aimed at a pane by name, continuations and background children still wait for that pane.
- A request fanned out to several panes is delivered by the app in one pass instead of one model call per pane. "Which one needs me" and "what's the result" answer from the pane record rather than by asking the model to read screens again. A finished Claude task now carries its result summary.
- Sends into an idle Codex 0.154 pane no longer fail with "may contain unsent user input" or "changed while I was about to type". Codex 0.154 repaints its empty composer many times a second as an ambient sparkle; the app now recognises the empty composer from the pane's real screen rather than counting bytes, and every Codex-family pane Lina opens starts with that animation switched off. A long prompt that Codex showed as "[Pasted Content …]" is now submitted.
- Every Orchestrator run through a real-app completion ladder of the user's own recorded requests (26 scenarios, 54 turns) found and fixed further defects: a pane that had never taken a prompt was never idle; a Codex question was invisible; every earlier unanswered question reached every later model call; a prose reply from the model ended the request; a one-millisecond clock skew between processes refused the first prompt into a new pane; a startup send was never retried. The final run passes 34 of 35 turns with the remaining one an allowed clarifying question and no harmful action.
- Kimi Code panes report waiting, working and done again. Kimi's own settings writer had been dropping the comment that marked Lina's hook entries, so every launch appended another set the app could not collect; one live config had reached 272 hook blocks. The strip is now content-based and the hooks follow Kimi 0.42's strict schema. Session discovery reads the 0.42 layout, and the bundled `kimi-custom` fork moves to 0.42.0.
- Agent panes are no longer paused after a reboot that interrupts the app's shutdown. The chat store now records that a shutdown was requested before any of its steps run, so only an exit that never reached the shutdown routine marks the previous run as needing recovery.

Repository source also includes prepared but disconnected login, session and
paid-access modules for the desktop, website and account server; they are built
only by their own tests, excluded from packaging, and normal startup is
unchanged. Only Codex and Claude panes were exercised by the completion ladder;
other providers are covered by their startup fixtures and hooks. Updates
preserve the user profile and apply through explicit Update / Restart.
