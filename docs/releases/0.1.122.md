# Lina Terminal 0.1.122

- The Orchestrator gets its first prompt into a terminal again. Every provider pane now waits for its own composer, recognized from the pane's real screen, before anything is typed. Claude panes were the worst case: the old rule required a shortcut hint Claude Code no longer prints, so every send waited out the startup budget and reported a launch timeout having typed nothing.
- A pane parked on a startup screen is reported as that screen — signing in, a folder-trust question, a self-update offer, a hook review — instead of being typed into. A folder-trust question for a project already registered in Lina, whose affirmative option is the one already highlighted, is answered automatically.
- Empty terminals are reused instead of duplicated. A pane that has never taken a prompt now counts as idle while its conversation identity is still provisional, and a pane held by a cancelled or failed request is released, so the Orchestrator stops opening a second terminal beside an empty one. Finished work keeps its terminal.
- A reply that both answers Lina's pending question and adds new work now does both. Previously the whole request was lost with a generic "could not interpret that request". The specific reason a request cannot be carried out also now reaches the task row, not only the conversation message.
- The bundled Codex runtime moves from 0.144.0 to 0.154.0, covering Fusion's planner/executor app-server, the Fusion model catalog and Open Codex. Current Codex settings files are written by 0.154 and the older bundled binary could not parse them, which silently dropped the user's model, approval, sandbox and trust settings in Fusion and emptied its model catalog. Codex-side effort is now low through ultra; a saved `minimal` selection normalizes to low instead of being dropped. An Open Codex turn now also asks the same model for a short task title, which is where the pane's generated name comes from and costs one extra small call.
- Chats is one flat list of the conversations started from the Chats section itself, newest first, each row showing provider, status and its project or folder. Panes opened from the terminal launcher or by the Orchestrator stay terminals and do not appear, and the sidebar no longer scans folders for provider history. The section collapses to its header and gives the height back to Projects.

Because no earlier row can be proven to have been started as a chat, the Chats
list begins empty after this upgrade. Every previous catalog row is kept in the
local database, only hidden, and existing terminals are unaffected.

Gemini and Codex Web panes reuse another provider's composer recognizer and have
not been confirmed against a live composer here; Cursor Agent has no captured
composer, so its panes keep their previous behavior and are typed into once they
paint something that is not a startup screen. Only the Windows x64 Codex bundles
were re-prepared. Repository source also includes the mobile client, isolated
account-server foundation and disconnected account/admin previews; hosted account
deployment, account integration and mobile store submission remain separate work.
Updates preserve the user profile and apply through explicit Update / Restart.
